# 1.0 is protocol-complete guild-bot coverage, not the whole bot-token catalog

`1.0` promises Gateway JSON bot-core (session, intents, sharding, rate limits, every official **Dispatch** plus unknown `t`, guild-Gateway send opcodes) and typed **Rest** for the guild-bot plus guild-admin Bot-token surface, including multipart on documented routes. It does not promise Discord’s full Bot-token catalog (monetization, Lobby, Identity, Activities, Voice protocol, Bearer-only command permissions, HTTP Interactions Endpoint URL as a release gate). Pre-1.0 work is four public `0.x` capability cuts: static REST transport, Gateway session, usable guild-bot (JSON), then scale (sharding, remaining typed dispatch/REST, attachments). Exact version numbers and CI gates: [Choose the delivery sequence and release gates](https://github.com/Ermianr/moon-discord/issues/13) (`docs/research/delivery-sequence-and-release-gates.md`).

**Considered options:** treat `1.0` as every inventory “in bot-core” REST row; ship a protocol-only `1.0` with semantic REST in `1.x`; require the HTTP Interactions Endpoint URL to tag `1.0`; make file uploads part of the usable-guild-bot cut. Those either inflate `1.0` with non-identity surfaces, contradict the map’s typed-Rest preference, couple the tag to Ed25519 on a compiler with no verify surface, or block the third cut on [Choose a static-tier encoding for Discord multipart REST](https://github.com/Ermianr/moon-discord/issues/14).

**Consequences:** REST-only (no `connect`, no cache) remains a supported `1.0` mode, matching [Choose the public Client experience](https://github.com/Ermianr/moon-discord/issues/4). That ADR’s `handleInteractionRequest` seam is not retracted; a working Interactions Endpoint URL is a `1.x` completeness item until [Choose how HTTP Interactions signatures verify on the static tier](https://github.com/Ermianr/moon-discord/issues/15) lands. Gateway receive plus HTTP callback/followups is the `1.0` interaction path. Deprecated pin/nick routes stay off typed **Rest** (use the **Rest hatch**). Detail: `docs/research/1.0-completeness-and-0.x-milestones.md`.
