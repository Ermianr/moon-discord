# Gateway session stays behind Client; five named sends; no live reshard

Gateway protocol (Hello, heartbeat ACK/zombie close ≠ 1000/1001, Resume vs Identify, close codes, `max_concurrency`, 120/60s, 4096-byte payloads, shard formula) is Discord’s. The product contract is a hidden **Session** per shard, `connect()` that waits for **READY**/**RESUMED** on owned sessions only (not `GUILD_CREATE`), constructor-only **Intents**, and five **Client** methods for application Gateway opcodes instead of a nested gateway object or an opcode hatch. `"recommended"` owns every shard in-process; omit + recommended count &gt; 1 fails before Identify; `{ id, count }` never auto-rescales. Reconnectable closes isolate to one Session; token/intent/shard fatals stop the **Client**. Last `updatePresence` is replayed on later Identify so re-Identify does not wipe status; request-members/soundboard/channel-info are send-only with results as **Dispatch**.

**Considered options:** public `ShardManager` / `client.gateway`; `connect()` waiting for all guilds; auto-shard on 4011 or live reshard; collecting `GUILD_MEMBERS_CHUNK` into a Promise of members; `shardId` on every `on` handler; constructor `presence` / `large_threshold` / `capabilities`. Those either leak session machinery, stall large bots, break multi-host `{ id, count }`, duplicate **Cache** as a member Promise, or grow Identify beyond the small **Client**.

**Consequences:** [Choose the public Client experience](https://github.com/Ermianr/moon-discord/issues/4) gains `updatePresence`, `updateVoiceState`, `requestGuildMembers`, `requestSoundboardSounds`, and `requestChannelInfo`. **Outbound model** applies to those bodies, not only Rest. Failure shapes stay [Define failure, cancellation, and backpressure semantics](https://github.com/Ermianr/moon-discord/issues/12). Detail: `docs/research/gateway-lifecycle-and-sharding.md`.
